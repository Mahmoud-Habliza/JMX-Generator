مولّد Test Plan لـ JMeter

Setup Login (once) + Main Thread Group (N users) — Sure QA

READY
1 بيئة النظام ⓘحدد هنا روابط النظام: رابط الـ Backend اللي هيستقبل طلب الـ Login، ورابط الـ Frontend اللي هتتصفح منه باقي الصفحات.
2 Setup — بيشتغل مرة واحدة بس ⓘالطلبات هنا بتتنفذ مرة واحدة بس قبل بداية الاختبار، مش لكل مستخدم. استخدمها لعملية الـ Login وأي طلب تحضيري تاني محتاج يحصل مرة واحدة.
Login + طلبات تحضيرية
Login Request (أساسي)
الـ Token بيتحفظ كـ Property مشترك، فهيتاخد مرة واحدة بغض النظر عن عدد المستخدمين في الـ Thread Group.
3 Main Thread Group — عدد المستخدمين ⓘحدد هنا عدد المستخدمين اللي عايز تحاكيهم، والمدة اللي هيوصلوا فيها لأقصى عدد، وكام مرة هيتكرر السيناريو لكل واحد فيهم.
ⓘعدد المستخدمين الوهميين اللي هيشتغلوا في نفس الوقت أثناء الاختبار.
ⓘالمدة بالثواني اللي هيوصل فيها JMeter لتشغيل كل المستخدمين تدريجيًا. مثلاً 5 مستخدمين مع Ramp-up = 10 ثواني، يعني هيبدأ مستخدم كل 2 ثانية.
ⓘعدد مرات تكرار السيناريو (سكشن 4) لكل مستخدم قبل ما ينتهي.
الأرقام دي بتخص السيناريو بس (تحت) — الـ Login مش هيتكرر عشانه.
4 السيناريو — بيتكرر لكل مستخدم ⓘالطلبات هنا بتتكرر لكل مستخدم من المستخدمين اللي حددتهم فوق، زي تصفح الصفحة الرئيسية أو صفحة الاجتماعات.
Home, Meetings, ...
5 Listeners — نوع التقارير ⓘاختار هنا شكل التقارير والنتائج اللي عايز تشوفها بعد ما الاختبار يخلص شغل.
التاليين محتاجين Plugin اسمه "jpgc - Standard Set" مُثبّت من الـ Plugins Manager بتاع JMeter — لو مش مُثبّت هيطلع Error زي "ClassNotFoundException":
اختار واحد أو أكتر — هيتضافوا في الملف كـ Listeners على مستوى الـ Test Plan.
